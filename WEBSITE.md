# OpportunityAI — Website

`index.html` is the whole application in **one self-contained file**: no Python, no server, no
install, no dependencies, and **no external network requests at all**. Double-click it and it runs.

---

## 1. Run it locally

**Simplest:** double-click `index.html` (or drag it into any browser).

If your browser restricts `file://` pages, serve it locally instead:

```bash
cd opportunity-ai
python3 -m http.server 8000
# open http://localhost:8000/index.html
```

Click **Try Demo Profile** to load a second-year Chemical Engineering student and populate everything.

---

## 2. Deploy it

Because it is one static file with no build step, any static host works. All free.

### GitHub Pages (recommended)

```bash
cd opportunity-ai
git init && git add . && git commit -m "OpportunityAI"
git branch -M main
git remote add origin https://github.com/<you>/opportunityai.git
git push -u origin main
```

Then on GitHub: **Settings → Pages → Source: Deploy from a branch → Branch: `main` / `root` → Save.**
Your site appears at `https://<you>.github.io/opportunityai/index.html` (or `/` if you move
`index.html` to the repo root).

### Netlify Drop

Go to `app.netlify.com/drop` and drag the `opportunity-ai` folder (or just `index.html`) onto the
page. You get a public URL in seconds — no account needed to try it.

### Cloudflare Pages / Vercel / any static host

Point it at the repository or upload `index.html`. No build command, no output directory settings —
it is already a static file.

### Offline / USB stick

Copy `index.html` to a USB stick. It works with no internet, which is a useful demo fallback if the
venue Wi-Fi fails.

## 4. What needs the Python app

These are deliberately **not** in the static site, and the UI says so rather than pretending:

- **Sarvam AI** explanations and translation. Calling the API from a static page would mean exposing
  your API key in client-side code — so the website runs the deterministic engine only.
- **PDF resume upload.** Parsing PDFs in-browser needs `pdf.js` from a CDN, which would break the
  offline guarantee. Paste the resume text instead (works offline), or use the Python app.
- **SQLite tracker.** The website uses `localStorage`, which persists per browser rather than per file.

Run those with `streamlit run app.py`.

---

## 5. Privacy

Everything runs in your browser. There is no analytics, no telemetry, and no outbound request — the
only URL in the file is the SVG XML namespace, which is not fetched. Your profile, tracker and chat
live in this browser's `localStorage`; **Delete my data** clears them. Resume text is kept in memory
only and is never persisted or transmitted.

---

## 6. How it stays correct

The website is not a mock-up: it runs the real engine, ported to JavaScript. To keep the two
implementations from drifting, `web/crosscheck.js` loads the JS engine and compares it against a
reference generated by the Python engine:

```bash
cd opportunity-ai/web
node crosscheck.js     # exits non-zero on any mismatch
```

It checks all 21 fit scores, every eligibility verdict, every timing status, the four radar panes,
the ranked Next-Best-Move actions (skill, priority, hours, gap) and the evidence labels. Current
result: **max fit delta 0.0000, zero mismatches.**

Two subtle things the port had to get right, both now covered by that check:

- `score_pct` is `total × 100` — an early version multiplied by 1000 and silently moved items between
  radar panes.
- rapidfuzz's `fuzz.ratio` is the *matching-blocks* ratio (`200·LCS / (len(a)+len(b))`), not a
  Levenshtein distance ratio. Using Levenshtein changed fuzzy skill credits.

## 7. Editing and rebuilding

The site is generated from five source files in `web/`:

```
web/engine.js      the engine (also runnable in Node)
web/app.js         UI logic, i18n dictionary, local assistant
web/styles.css     styling
web/template.html  the static shell
web/build.py       inlines data + css + engine + app → index.html
```

After any edit:

```bash
cd opportunity-ai
python3 web/build.py        # rewrites index.html
python3 -m pytest tests -q  # the Python engine's own tests still pass
```

`build.py` reads `data/opportunities.json` and `data/knowledge.json` directly, so the website and the
Python app always share one dataset. It also asserts that no template placeholder or citation marker
leaks into the output.

---

## 8. Notes and limitations

- The dataset is 21 illustrative **sample** records with fictional organisations. No deadline, link or
  eligibility claim is asserted as true, and every unknown field is labelled.
- Fit is guidance, not a prediction of selection — stated in the UI.
- The Hindi interface covers the shell and dynamic content; skill names, organisation names and
  technical terms stay in English by design.
- The font stack is system fonts, so there is no font download; typography degrades gracefully.
- Roughly 150 KB, one file, zero dependencies.
